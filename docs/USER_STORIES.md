# DormDee — ความต้องการผู้ใช้และ User Stories

**ขอบเขต:** ระบบบัญชีและการเริ่มต้นใช้งาน สำหรับวางแผนการพัฒนา  
**ฉบับ:** 1.1

## ภาพรวม

### เริ่มใช้งานง่าย ไม่ว่าจะหาหอหรือเป็นเจ้าของหอ

DormDee มีเป้าหมายให้ผู้เช่าหาหอพักที่ตรงความต้องการ เห็นข้อมูลห้องว่างและค่าใช้จ่ายชัดเจน พร้อมติดต่อเจ้าของหอได้สะดวก จุดเริ่มต้นของประสบการณ์นี้คือการเข้าใจบริการ สมัครบัญชี และเข้าสู่พื้นที่ที่เหมาะกับตนเองได้ง่าย

### เป้าหมายของเอกสาร

กำหนดความต้องการของผู้ใช้ในรูปแบบ 12 User Stories พร้อมเกณฑ์การยอมรับ เพื่อให้ทีมผลิตภัณฑ์ ออกแบบ พัฒนา และทดสอบเข้าใจผลลัพธ์ที่ต้องส่งมอบตรงกันก่อนเริ่มงาน

### กลุ่มผู้ใช้งาน

| กลุ่มผู้ใช้ | ความต้องการ |
|---|---|
| ผู้เยี่ยมชม | ต้องการรู้จักบริการและเริ่มใช้งาน |
| ผู้เช่า | ต้องการบัญชีสำหรับใช้บริการหอพัก |
| เจ้าของหอ | ต้องการเริ่มต้นใช้งานเพื่อลงประกาศ |

### ผลลัพธ์ที่ต้องการ

ผู้ใช้เลือกเส้นทางได้ตรงบทบาท สมัครและเข้าสู่ระบบได้สะดวก จัดการบัญชีของตนเองได้ และเข้าใจขั้นตอนถัดไปโดยไม่ต้องขอความช่วยเหลือ

### ขอบเขตของชุด User Stories

- รู้จักบริการ
- สมัครบัญชี
- เข้าสู่ระบบด้วยอีเมลหรือ Google
- จัดการข้อมูลบัญชี
- เข้าถึงพื้นที่ส่วนตัว
- เริ่มต้นใช้งานฝั่งเจ้าของหอ
- ออกจากระบบ
- เลือกธีม
- กู้คืนรหัสผ่าน
- ขอลิงก์ยืนยันอีเมลใหม่
- ลบบัญชีและขอข้อมูลส่วนบุคคล

### ข้อกำหนดที่ใช้กับทุก Story

- ใช้งานได้ครบบนมือถือ (ความกว้างหน้าจอตั้งแต่ 375px) เท่ากับบนเดสก์ท็อป
- ข้อความแจ้งผลและข้อผิดพลาดเป็นภาษาไทย บอกทั้งสาเหตุและสิ่งที่ผู้ใช้ทำต่อได้
- ไม่แสดงปุ่ม ลิงก์ หรือตัวเลือกที่ยังใช้งานไม่ได้ หากจำเป็นต้องแสดง ให้ติดป้าย "เร็ว ๆ นี้"
- ไม่ใช้คำภายในทีม (เช่น Phase, MVP) ในข้อความที่ผู้ใช้เห็น

### งานที่แยกกำหนดรายละเอียดเพิ่มเติม

การสร้างและเผยแพร่หอพัก การจัดการห้อง การค้นหาและแผนที่ หน้ารายละเอียดหอ การแชท การจอง และการคำนวณค่าใช้จ่าย จะจัดทำเป็น User Stories แยกจากเอกสารชุดนี้

### แนวทางการตรวจรับ

พิจารณาจากสิ่งที่ผู้ใช้ทำได้และผลลัพธ์ที่มองเห็น โดยใช้เกณฑ์ใต้แต่ละ Story เป็นแนวทางออกแบบหน้าจอและทดสอบ ทั้งกรณีสำเร็จและกรณีที่ผู้ใช้ต้องแก้ไขข้อมูล

## เริ่มรู้จักและสร้างบัญชี

ให้ผู้ใช้เข้าใจบริการและเลือกเส้นทางที่เหมาะกับตนเอง

### US-01: รู้จักบริการก่อนเริ่มใช้งาน

ในฐานะผู้ที่กำลังมองหาหอพัก ฉันอยากรู้ว่า DormDee ช่วยฉันหาหอได้อย่างไร และเริ่มใช้งานตรงไหน เพื่อจะได้เลือกทางไปต่อได้ง่าย

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. หน้าแรกอธิบายประโยชน์ของบริการด้วยภาษาที่เข้าใจง่าย ได้แก่ ห้องว่างจริง การจองผ่านแชท และค่าใช้จ่ายที่ชัดเจน
2. ผู้ที่กำลังหาหอเห็นทางเข้าสู่การค้นหาหอพักได้อย่างชัดเจน
3. เจ้าของหอสามารถเริ่มสมัครบัญชีจากปุ่มลงประกาศ โดยเลือกบทบาทเจ้าของหอไว้ให้
4. ประโยชน์หรือฟีเจอร์ที่ยังไม่เปิดให้ใช้ ต้องติดป้าย "เร็ว ๆ นี้" และทางเข้าการค้นหาต้องพาไปหน้าที่ใช้งานได้ หรือบอกผู้ใช้ว่าการค้นหายังไม่เปิดให้ใช้

### US-02: สมัครด้วยอีเมลและเลือกบทบาท

ในฐานะผู้ใช้ใหม่ ฉันอยากสมัครด้วยอีเมล และบอกว่าฉันเป็นผู้เช่าหรือเจ้าของหอ เพื่อให้เริ่มใช้งานได้ตรงกับสิ่งที่ต้องการ

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. ผู้ใช้กรอกชื่อ อีเมล รหัสผ่าน และเลือกเป็นผู้เช่าหรือเจ้าของหอได้ โดยรหัสผ่านต้องมีอย่างน้อย 8 ตัวอักษร
2. หากต้องยืนยันอีเมล ระบบบอกขั้นตอนถัดไปอย่างชัดเจน เพื่อให้ผู้ใช้รู้ว่าต้องทำอะไร
3. เมื่อสมัครและยืนยันตัวตนสำเร็จ เจ้าของหอเข้าสู่พื้นที่สำหรับเจ้าของหอ ส่วนผู้เช่าเข้าสู่หน้าแรก
4. ก่อนสมัคร ผู้ใช้เห็นลิงก์เงื่อนไขการใช้งานและนโยบายความเป็นส่วนตัว และการสมัครถือเป็นการยอมรับ (หรือมีช่องให้ยอมรับ ตามที่ฝ่ายกฎหมายกำหนด)
5. หากอีเมลนี้มีบัญชีอยู่แล้ว ระบบแนะนำให้เข้าสู่ระบบแทน

### US-03: กลับมาเข้าสู่ระบบ

ในฐานะสมาชิกที่มีบัญชีแล้ว ฉันอยากใช้อีเมลและรหัสผ่านเข้าใช้งาน และกลับไปยังหน้าที่ตั้งใจเปิด เพื่อไม่ต้องเริ่มเดินหาเมนูใหม่

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. เมื่อกรอกอีเมลและรหัสผ่านถูกต้อง สมาชิกสามารถเข้าสู่ระบบได้
2. หากสมาชิกถูกพามาเข้าสู่ระบบจากหน้าที่ต้องการใช้งาน เมื่อเข้าสำเร็จต้องกลับไปหน้านั้นได้
3. หากข้อมูลไม่ถูกต้องหรือยังไม่ได้ยืนยันอีเมล ระบบแจ้งสาเหตุและแนวทางดำเนินการเป็นภาษาไทย กรณียังไม่ยืนยันอีเมล ต้องมีทางขอลิงก์ยืนยันใหม่ (ดู US-11)
4. หน้าเข้าสู่ระบบมีลิงก์ "ลืมรหัสผ่าน" ที่ใช้งานได้ (ดู US-10)

## เข้าใช้และดูแลบัญชี

เข้าใช้งานสะดวก พร้อมดูแลข้อมูลและการเข้าถึงบัญชี

### US-04: ใช้บัญชี Google ได้สะดวก

ในฐานะผู้ใช้ที่มีบัญชี Google ฉันอยากใช้ Google สมัครหรือเข้าสู่ระบบ เพื่อไม่ต้องสร้างรหัสผ่านสำหรับบริการนี้เพิ่ม

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. ผู้ใช้เลือกสมัครหรือเข้าสู่ระบบด้วยบัญชี Google ได้ โดยไม่ต้องตั้งรหัสผ่านใหม่สำหรับ DormDee
2. เมื่อสมัครด้วย Google ระบบคงบทบาทผู้เช่าหรือเจ้าของหอตามที่ผู้ใช้เลือกไว้
3. หากเข้าสู่ระบบด้วย Google ไม่สำเร็จ ระบบแจ้งปัญหาและเสนอให้ใช้อีเมลแทน ทั้งกรณีที่ล้มเหลวก่อนออกไปหน้า Google และกรณีที่ล้มเหลวหลังกลับมาจาก Google
4. หากผู้ใช้ที่มีบัญชีผู้เช่าอยู่แล้วกดสมัครด้วย Google โดยเลือกเจ้าของหอ ระบบทำตามข้อตกลงในหัวข้อ "คำถามที่ต้องตัดสินใจ" ข้อ 2

### US-05: ดูแลข้อมูลบัญชีของตัวเอง

ในฐานะสมาชิกที่เข้าสู่ระบบแล้ว ฉันอยากแก้ชื่อที่แสดงและเปลี่ยนบทบาทการใช้งาน เพื่อให้บัญชีตรงกับการใช้งานของฉันในตอนนี้

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. สมาชิกดูอีเมลและแก้ไขชื่อที่แสดงได้ โดยการเปลี่ยนอีเมลอยู่นอกขอบเขตของฟอร์มนี้
2. สมาชิกทั่วไปสลับบทบาทระหว่างผู้เช่ากับเจ้าของหอได้ และต้องกรอกชื่อก่อนบันทึก
3. เมื่อบันทึกสำเร็จ ระบบแจ้งผลและแสดงข้อมูลใหม่ หากบันทึกไม่ได้ต้องมีข้อความอธิบาย
4. เจ้าของหอที่มีหอพักอยู่ในระบบแล้ว เปลี่ยนเป็นผู้เช่าได้ตามข้อตกลงในหัวข้อ "คำถามที่ต้องตัดสินใจ" ข้อ 1

### US-06: เข้าใช้หน้าส่วนตัวอย่างปลอดภัย

ในฐานะสมาชิกของเว็บไซต์ ฉันอยากให้หน้าบัญชีและพื้นที่เจ้าของหอต้องเข้าสู่ระบบก่อน เพื่อให้การทำงานในพื้นที่เหล่านี้ผูกกับบัญชีของฉัน

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. ผู้ที่ยังไม่เข้าสู่ระบบต้องเข้าสู่ระบบก่อนเปิดหน้าบัญชีหรือพื้นที่เจ้าของหอ
2. หลังเข้าสู่ระบบสำเร็จ สมาชิกกลับไปยังหน้าที่ต้องการใช้งานได้โดยไม่ต้องเริ่มใหม่
3. ระบบต้องยืนยันตัวตนก่อนแสดงข้อมูลบัญชี และไม่พาผู้ใช้ไปยังเว็บไซต์ภายนอกจากขั้นตอนเข้าสู่ระบบ

## เริ่มใช้งานและกลับมาอีกครั้ง

มีขั้นตอนถัดไปที่ชัดเจน และประสบการณ์ที่ใช้งานสบาย

### US-07: เริ่มต้นใช้งานในฐานะเจ้าของหอ

ในฐานะสมาชิกที่สนใจลงประกาศหอพัก ฉันอยากมีพื้นที่สำหรับเจ้าของหอที่บอกขั้นตอนเริ่มต้นชัดเจน เพื่อเตรียมลงประกาศได้โดยไม่สับสน

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. เจ้าของหอเห็นจุดเริ่มต้นและคำแนะนำสำหรับการลงประกาศหอพักแห่งแรก เป็นขั้นตอนที่อ่านแล้วรู้ว่าต้องเตรียมอะไร (เช่น รูปหอ ที่ตั้ง ประเภทห้อง ราคา และค่าน้ำค่าไฟ) และมีปุ่มเริ่มสร้างหอเมื่อฟีเจอร์เปิดใช้
2. ผู้เช่าที่เข้ามาในพื้นที่นี้เห็นคำอธิบายว่าต้องเปลี่ยนบทบาทก่อนเริ่มลงประกาศ
3. ผู้ใช้ไปยังหน้าจัดการบัญชีเพื่อเปลี่ยนบทบาทได้โดยตรง ทั้งนี้เรื่องนี้ครอบคลุมเฉพาะทางเข้าพื้นที่เจ้าของหอ
4. หากการสร้างหอยังไม่เปิดให้ใช้ ข้อความต้องบอกผู้ใช้ด้วยภาษาทั่วไป (เช่น "เร็ว ๆ นี้") ไม่ใช้คำภายในทีม

### US-08: ออกจากระบบเมื่อใช้งานเสร็จ

ในฐานะสมาชิกที่เข้าสู่ระบบแล้ว ฉันอยากออกจากระบบได้เมื่อใช้งานเสร็จ เพื่อจบการใช้งานบัญชีบนอุปกรณ์นี้

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. สมาชิกพบคำสั่งออกจากระบบได้ในเมนูบัญชี
2. เมื่อออกจากระบบสำเร็จ ระบบพากลับหน้าแรกและเปลี่ยนเมนูเป็นสถานะผู้เยี่ยมชม
3. หากกลับไปเปิดหน้าส่วนตัวหลังออกจากระบบ ต้องเข้าสู่ระบบอีกครั้ง

### US-09: เลือกธีมที่อ่านสบายตา

ในฐานะผู้ใช้งานเว็บไซต์ ฉันอยากเลือกธีมสว่างหรือมืด และให้เว็บจำตัวเลือกไว้ เพื่อกลับมาใช้งานครั้งต่อไปได้สบายตาเหมือนเดิม

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. ผู้ใช้เลือกธีมสว่างหรือมืดได้ และหน้าจอเปลี่ยนตามตัวเลือกโดยทันที
2. เมื่อกลับมาใช้งานบนเบราว์เซอร์เดิม ระบบจดจำธีมที่เลือกไว้ได้หากอุปกรณ์อนุญาต
3. เมื่อเปิดหน้าใหม่ ระบบแสดงธีมที่เลือกไว้อย่างต่อเนื่อง เพื่อลดการกะพริบของหน้าจอ
4. ตัวเลือกธีมใช้ได้ทั้งบนเดสก์ท็อปและมือถือ ทั้งตอนเข้าสู่ระบบและไม่ได้เข้าสู่ระบบ

## กู้คืนและดูแลสิทธิ์ในบัญชี

ผู้ใช้กลับเข้าบัญชีได้เองเมื่อติดปัญหา และควบคุมข้อมูลของตนเองได้

### US-10: ตั้งรหัสผ่านใหม่เมื่อลืม

ในฐานะสมาชิกที่ลืมรหัสผ่าน ฉันอยากขอลิงก์ตั้งรหัสผ่านใหม่ทางอีเมล เพื่อกลับเข้าใช้บัญชีเดิมได้โดยไม่ต้องติดต่อทีมงาน

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. จากหน้าเข้าสู่ระบบ สมาชิกกด "ลืมรหัสผ่าน" แล้วกรอกอีเมลเพื่อขอลิงก์ได้
2. ระบบแสดงข้อความเดียวกันไม่ว่าอีเมลนั้นจะมีบัญชีหรือไม่ เพื่อไม่เปิดเผยว่าใครเป็นสมาชิก
3. เมื่อเปิดลิงก์ สมาชิกตั้งรหัสผ่านใหม่ (อย่างน้อย 8 ตัวอักษร) แล้วเข้าสู่ระบบได้ทันที
4. ลิงก์ที่หมดอายุหรือใช้ไปแล้ว ระบบแจ้งเป็นภาษาไทยและให้ขอลิงก์ใหม่ได้

### US-11: ขอลิงก์ยืนยันอีเมลใหม่

ในฐานะผู้สมัครที่ยังไม่ได้ยืนยันอีเมล ฉันอยากขอลิงก์ยืนยันใหม่ เมื่อไม่ได้รับอีเมลหรือลิงก์หมดอายุ เพื่อเริ่มใช้งานได้โดยไม่ต้องสมัครใหม่

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. หลังสมัคร และเมื่อเข้าสู่ระบบแล้วพบว่ายังไม่ยืนยันอีเมล ผู้ใช้เห็นปุ่มขอลิงก์ยืนยันใหม่
2. ระบบแจ้งว่าส่งลิงก์แล้ว และแนะนำให้ตรวจโฟลเดอร์จดหมายขยะ
3. หากขอบ่อยเกินกำหนด ระบบบอกให้รอและบอกระยะเวลาที่ต้องรอ

### US-12: ลบบัญชีและขอข้อมูลส่วนบุคคล

ในฐานะสมาชิก ฉันอยากขอลบบัญชีหรือขอสำเนาข้อมูลส่วนบุคคลของฉัน เพื่อใช้สิทธิ์ของเจ้าของข้อมูลตาม PDPA

**เกณฑ์การยอมรับ (Acceptance Criteria)**

1. หน้าบัญชีมีทางขอลบบัญชี โดยอธิบายว่าข้อมูลใดจะถูกลบและข้อมูลใดต้องเก็บไว้ตามกฎหมาย
2. ก่อนลบ ระบบให้ยืนยันอีกครั้ง และเมื่อลบแล้วจะออกจากระบบทันที
3. สมาชิกขอสำเนาข้อมูลส่วนบุคคลของตนเองได้ (ดาวน์โหลดหรือส่งทางอีเมล ตามที่ทีมกำหนด)
4. เจ้าของหอที่มีหอพักหรือการจองค้างอยู่ ระบบแจ้งสิ่งที่ต้องจัดการก่อนลบบัญชี

## คำถามที่ต้องตัดสินใจ

1. **เจ้าของหอที่มีหอพักแล้วเปลี่ยนเป็นผู้เช่า (US-05):** อนุญาตหรือไม่ ถ้าอนุญาต หอที่เผยแพร่อยู่จะถูกซ่อน ถูกเก็บถาวร หรือยังแสดงต่อ
2. **บัญชี Google กับบทบาทเดิม (US-04):** ผู้ใช้ที่เป็นผู้เช่าอยู่แล้ว กดสมัครด้วย Google แล้วเลือกเจ้าของหอ ระบบควรเปลี่ยนบทบาทให้เลย ถามก่อน หรือคงบทบาทเดิม (ตอนนี้ระบบเปลี่ยนให้โดยไม่ถาม)
3. **อีเมลซ้ำระหว่าง Google กับอีเมลและรหัสผ่าน (US-04):** รวมเป็นบัญชีเดียว หรือแจ้งให้ผู้ใช้เข้าสู่ระบบด้วยวิธีเดิม
4. **การยืนยันอีเมลบน production (US-02):** บังคับยืนยันก่อนใช้งานหรือไม่ (ตอนพัฒนาบนเครื่องปิดไว้)
5. **การยอมรับเงื่อนไข (US-02):** ต้องมีช่องให้ติ๊กยอมรับ หรือใช้ข้อความ "การสมัครถือว่ายอมรับ" ก็เพียงพอ
