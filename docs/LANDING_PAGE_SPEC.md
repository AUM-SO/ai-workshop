# Landing Page Spec – DormDee

สเปกของหน้า landing page (`/`) ที่มาแทนหน้าแรกปัจจุบัน (hero + การ์ด 3 ใบ ใน `app/page.tsx`)

- Branch: `feature/landing-page` (แตกจาก `develop`, merge กลับด้วย `--no-ff`)
- อ้างอิง: [PRODUCT_PLAN.md](PRODUCT_PLAN.md), [ROADMAP.md](ROADMAP.md), กฎ UI ใน `AGENTS.md`

## 1. เป้าหมาย

หน้าแรกต้องทำ 2 อย่างให้จบภายในหน้าจอแรก:

1. **ผู้เช่า** เข้าใจทันทีว่า DormDee ต่างจากเว็บประกาศทั่วไปอย่างไร (ห้องว่างจริง, ค่าใช้จ่ายครบ, จองในแชท) และเริ่มค้นหาได้จาก hero เลย
2. **เจ้าของหอ** เห็นว่าลงหอฟรีและจัดการห้อง + ตอบแชท + รับจองได้ในที่เดียว แล้วกดสมัครแบบเจ้าของหอ

### ตัวชี้วัด (เก็บเมื่อมี analytics)

| Metric | นิยาม |
|--------|-------|
| Search start rate | % ผู้เข้าชม `/` ที่ส่งฟอร์มค้นหาใน hero หรือคลิกทำเลยอดนิยม |
| Owner signup rate | % ผู้เข้าชมที่คลิก CTA เจ้าของหอ แล้วสมัครสำเร็จ (`/signup?role=owner`) |
| Scroll depth | % ที่เลื่อนถึง FAQ |

## 2. กลุ่มเป้าหมาย

| กลุ่ม | สิ่งที่อยากรู้ | CTA หลัก |
|------|---------------|----------|
| นักศึกษา / คนทำงานที่หาห้องรายเดือน (มือถือเป็นหลัก) | ห้องว่างจริงไหม, จ่ายวันเข้าอยู่เท่าไร, ปลอดภัยไหม | ค้นหาหอพัก (`/search`) |
| เจ้าของหอขนาดเล็ก–กลาง | ฟรีไหม, ยุ่งยากไหม, ได้ผู้เช่าจริงไหม | ลงประกาศหอพักฟรี (`/signup?role=owner`) |

## 3. หลักการเนื้อหา

- **ไม่สัญญาสิ่งที่ยังไม่มี**: ฟีเจอร์ที่ยังไม่ออก (ดูคอลัมน์ "สถานะ" ในหัวข้อ 5) ต้องติดป้าย `เร็ว ๆ นี้` หรือไม่แสดงเลย
- **ไม่มีตัวเลขปลอม**: ไม่ใส่ "หอพัก 10,000+ แห่ง" หรือรีวิวสมมติ ส่วนตัวเลขสถิติจะแสดงเมื่อดึงจากฐานข้อมูลจริงได้แล้วเท่านั้น (หัวข้อ 5.4)
- ภาษาไทยเป็นหลัก น้ำเสียงเป็นกันเอง ประโยคสั้น พูดถึงปัญหาที่ผู้ใช้เจอจริง

## 4. โครงหน้า (ลำดับ section)

```
SiteHeader (มีอยู่แล้ว)
1. Hero + ช่องค้นหา + ภาพตัวอย่าง Live Room Map
2. ปัญหา → ทางออก
3. ฟีเจอร์สำหรับผู้เช่า
4. ใช้งานยังไง (สลับ ผู้เช่า / เจ้าของหอ)
5. สำหรับเจ้าของหอ
6. ทำเลยอดนิยม
7. ความปลอดภัย
8. คำถามที่พบบ่อย (FAQ)
9. CTA ปิดท้าย
SiteFooter (ใหม่)
```

## 5. รายละเอียดแต่ละ section

### 5.1 Hero

| ส่วน | เนื้อหา |
|------|---------|
| Eyebrow (chip) | `ห้องว่างอัปเดตแบบ real-time` |
| H1 | หาหอพักที่ว่างจริง และจองได้ทันทีผ่านแชท |
| Sub | ค้นหาหอใกล้มหาวิทยาลัย ที่ทำงาน หรือรถไฟฟ้า เห็นค่าใช้จ่ายทั้งหมดก่อนตัดสินใจ แล้วคุยกับเจ้าของหอโดยตรง |
| ช่องค้นหา | `SearchField` placeholder "ชื่อมหาวิทยาลัย, สถานี BTS/MRT หรือย่าน" + ปุ่ม "ค้นหา" → `GET /search?q=<คำค้น>` (ฟอร์ม HTML ธรรมดา ใช้งานได้แม้ JS ยังโหลดไม่เสร็จ) |
| CTA รอง | ลิงก์ "เป็นเจ้าของหอ? ลงประกาศฟรี" → `/signup?role=owner` |
| ภาพประกอบ | การ์ดจำลอง **Live Room Map**: กริดห้อง 2 ชั้น × 6 ห้อง ใช้สีสถานะ ว่าง / ติดจอง / มีผู้เช่า พร้อม legend ทำเป็นคอมโพเนนต์ (ไม่ใช่รูปภาพ) ใช้ข้อมูลตัวอย่างคงที่ และมีป้าย "ตัวอย่าง" |

Layout: เดสก์ท็อป 2 คอลัมน์ (ข้อความซ้าย, ภาพขวา); มือถือเรียงเป็นแนวตั้ง โดยช่องค้นหาต้องอยู่ในหน้าจอแรก (above the fold ที่ 375×812)

### 5.2 ปัญหา → ทางออก

การ์ด 3 ใบ แต่ละใบมี "ปัญหาที่เจอ" (text-secondary) และ "DormDee ช่วยยังไง":

| ปัญหา | ทางออก |
|-------|--------|
| ทักไปแล้วห้องเต็ม ประกาศค้างเป็นเดือน | สถานะห้องมาจากระบบจัดการหอโดยตรง ห้องไหนถูกจอง ประกาศเปลี่ยนทันที |
| ไปถึงวันเข้าอยู่แล้วเจอค่าใช้จ่ายเพิ่ม | แสดงเงินวันเข้าอยู่ + ค่าน้ำค่าไฟโดยประมาณก่อนตัดสินใจ |
| โดนหลอกโอนมัดจำก่อนดูห้อง | การจองยืนยันในระบบ พร้อมคำเตือนเมื่อมีการขอโอนเงินนอกระบบ |

### 5.3 ฟีเจอร์สำหรับผู้เช่า

Grid การ์ดฟีเจอร์ (ไอคอน + หัวข้อ + คำอธิบาย 1–2 บรรทัด):

| ฟีเจอร์ | ไอคอน (Remix) | สถานะตอนเปิดหน้า |
|---------|---------------|------------------|
| ห้องว่างจริง (Live Room Map) | `RiLayoutGridLine` | แสดง (Phase 2) |
| จองผ่านแชท (Chat-to-Book) | `RiChat3Line` | แสดง (Phase 3) |
| คำนวณค่าเข้าอยู่ (Move-in Cost) | `RiWallet3Line` | แสดง (Phase 2) |
| แจ้งเตือนเมื่อห้องว่าง (Waitlist) | `RiNotification3Line` | ป้าย `เร็ว ๆ นี้` (Phase 4) |
| ค้นหาตามเวลาเดินทาง | `RiRouteLine` | ป้าย `เร็ว ๆ นี้` (Phase 5) |
| หาเพื่อนร่วมห้อง | `RiGroupLine` | ป้าย `เร็ว ๆ นี้` (Phase 5) |

Move-in Cost มี **mini demo**: ใส่ค่าเช่า/เดือน (`NumberField`), จำนวนเดือนล่วงหน้า และเดือนมัดจำ แล้วแสดงยอดที่ต้องจ่ายวันเข้าอยู่ทันที (คำนวณฝั่ง client ไม่ต้องเรียก DB) ค่าเริ่มต้น 4,500 บาท, ล่วงหน้า 1 เดือน, มัดจำ 2 เดือน → 13,500 บาท

### 5.4 ตัวเลขจริง (แสดงแบบมีเงื่อนไข)

แถบสถิติ 3 ช่อง: จำนวนหอที่ publish, จำนวนห้องว่างตอนนี้, จำนวนจังหวัด
- ดึงจาก Supabase (เฉพาะ `dorms.status = 'published'` ผ่าน RLS ของ anon)
- **ซ่อนทั้ง section** ถ้าหอที่ publish น้อยกว่า 20 แห่ง
- ข้อมูลแคชได้ (`"use cache"` + `cacheLife('hours')`) เพราะไม่ต้องเรียลไทม์

### 5.5 ใช้งานยังไง

`SegmentedControl` สลับ "ผู้เช่า" / "เจ้าของหอ" แต่ละแบบมี 3 ขั้น เป็นรายการลำดับ (`<ol>`):

| ผู้เช่า | เจ้าของหอ |
|---------|-----------|
| 1. ค้นหาหอใกล้ที่เรียนหรือที่ทำงาน | 1. สมัครแล้วสร้างหอ ใส่รูปและที่ตั้ง |
| 2. ดูห้องที่ว่างจริงและค่าใช้จ่ายทั้งหมด | 2. เพิ่มประเภทห้องและเลขห้อง ระบบสร้างผังห้องให้ |
| 3. กด "แชทเพื่อจอง" ส่งคำขอ แล้วรอเจ้าของยืนยัน | 3. ตอบแชทและกดยืนยันการจอง สถานะห้องอัปเดตเอง |

ค่าเริ่มต้น: "ผู้เช่า" ถ้า URL มี `?for=owner` ให้เปิดแท็บเจ้าของหอ (ใช้กับลิงก์จากเมนู "สำหรับเจ้าของหอ" ตอนผู้ใช้ยังไม่ล็อกอิน)

### 5.6 สำหรับเจ้าของหอ

แบ่ง 2 คอลัมน์: ข้อความซ้าย + รายการจุดเด่นขวา

- H2: ลงหอพักฟรี จัดการห้องและการจองในที่เดียว
- จุดเด่น (check list):
  - ลงประกาศฟรี ไม่จำกัดจำนวนห้อง
  - ผังห้องรายชั้น เปลี่ยนสถานะได้ในคลิกเดียว
  - กล่องแชทรวมผู้สนใจทุกคน พร้อมการ์ดคำขอจอง
  - แจ้งเตือนผ่าน LINE — ป้าย `เร็ว ๆ นี้`
  - ป้าย Verified สร้างความน่าเชื่อถือ — ป้าย `เร็ว ๆ นี้`
- CTA: "ลงประกาศหอพักฟรี" → `/signup?role=owner`; ถ้าล็อกอินเป็น owner แล้ว เปลี่ยนเป็น "ไปที่หอของฉัน" → `/owner`

### 5.7 ทำเลยอดนิยม

รายการลิงก์ทรง pill (`rounded-full`) → `/search?q=<ชื่อ>` ข้อมูลคงที่ในไฟล์ `app/(landing)/popular-areas-data.ts`:

มหาวิทยาลัย: จุฬาฯ, ม.เกษตรศาสตร์, ม.ธรรมศาสตร์ รังสิต, ม.มหิดล ศาลายา, ม.ศรีนครินทรวิโรฒ, สจล. ลาดกระบัง, ม.เชียงใหม่, ม.ขอนแก่น
รถไฟฟ้า: BTS อนุสาวรีย์ชัยฯ, BTS อ่อนนุช, MRT ห้วยขวาง, MRT ลาดพร้าว

(เปลี่ยนเป็นข้อมูลจริงจาก DB ได้ใน Phase 2 เมื่อมีหอพอ)

### 5.8 ความปลอดภัย

3 ข้อ (ไอคอน `RiShieldCheckLine`, `RiAlertLine`, `RiStarLine`):

1. อย่าโอนมัดจำก่อนดูห้องหรือก่อนยืนยันการจองในระบบ
2. ระบบเตือนเมื่อมีการขอโอนเงินนอกระบบในแชท — `เร็ว ๆ นี้`
3. รีวิวได้เฉพาะคนที่จองผ่านระบบจริง — `เร็ว ๆ นี้`

### 5.9 FAQ

`Accordion` แบบ separated, 6 ข้อ:

| คำถาม | คำตอบ |
|-------|-------|
| ใช้ DormDee เสียค่าใช้จ่ายไหม | ผู้เช่าใช้ฟรีทั้งหมด เจ้าของหอลงประกาศฟรี |
| "ห้องว่างจริง" หมายความว่าอะไร | สถานะห้องมาจากผังห้องที่เจ้าของหอใช้จัดการหอ เมื่อห้องถูกจองหรือมีผู้เช่า สถานะจะเปลี่ยนทันที |
| จองผ่านแชทแล้วต้องจ่ายเงินเลยไหม | ยังไม่ต้อง การจองคือการขอจองห้องกับเจ้าของหอ การชำระเงินตกลงกันหลังเจ้าของยืนยัน และควรดูห้องก่อนโอนเงิน |
| ค่าเข้าอยู่คำนวณยังไง | ค่าเช่าล่วงหน้า + เงินมัดจำ + ค่าธรรมเนียมอื่นที่เจ้าของหอระบุ ส่วนค่าน้ำค่าไฟเป็นค่าประมาณตามการใช้งาน |
| เจ้าของหอต้องมีเอกสารอะไรบ้าง | สมัครและลงหอได้ทันที การยืนยันตัวตนเพื่อรับป้าย Verified จะเปิดในเร็ว ๆ นี้ |
| ข้อมูลส่วนตัวของฉันปลอดภัยไหม | เบอร์โทรและข้อมูลส่วนตัวไม่แสดงต่อสาธารณะ เจ้าของหอเห็นเฉพาะข้อมูลที่จำเป็นต่อการจอง |

FAQ ส่ง JSON-LD `FAQPage` ด้วย (หัวข้อ 7)

### 5.10 CTA ปิดท้าย

แถบเต็มความกว้าง พื้น `bg-background-secondary-default`, `rounded-3xl`
- H2: พร้อมหาห้องหรือยัง
- ปุ่มหลัก "ค้นหาหอพัก" → `/search`, ปุ่มรอง "ลงประกาศหอพักฟรี" → `/signup?role=owner`

### 5.11 SiteFooter (ใหม่ ใช้ทุกหน้า)

- โลโก้ + คำอธิบาย 1 บรรทัด
- คอลัมน์ลิงก์: ผู้เช่า (ค้นหาหอพัก, ทำเลยอดนิยม) / เจ้าของหอ (ลงประกาศฟรี, เข้าสู่ระบบ) / เกี่ยวกับ (คำถามที่พบบ่อย `#faq`, นโยบายความเป็นส่วนตัว, เงื่อนไขการใช้งาน)
- หน้านโยบาย/เงื่อนไขยังไม่มี → ทำเป็นหน้า placeholder ใน branch เดียวกัน (`/privacy`, `/terms`) เพราะ PDPA ต้องมี
- `© 2026 DormDee` (ใช้ปีปัจจุบันแบบคงที่ตอน build เพื่อไม่ให้ต้องเรนเดอร์ตอน request)

## 6. UI และ component

ตามกฎใน `AGENTS.md`:

| ใช้ | Component / utility |
|-----|---------------------|
| ปุ่ม/ลิงก์ CTA | `ButtonLink` จาก `@/components/base/buttons/button` |
| ช่องค้นหา hero | `search-field` (ติดตั้งเพิ่ม `npx boardui@latest add search-field`) |
| ป้ายสถานะ, `เร็ว ๆ นี้`, eyebrow | `chip` (ติดตั้งเพิ่ม) |
| สลับผู้เช่า/เจ้าของ | `segmented-control` (ติดตั้งเพิ่ม) |
| FAQ | `accordion` (ติดตั้งเพิ่ม) |
| mini calculator | `number-field` (ติดตั้งเพิ่ม) |
| ผังห้องตัวอย่าง | คอมโพเนนต์ใหม่ `components/dorm/room-grid.tsx` — ออกแบบให้ Phase 1–2 นำไปใช้ต่อกับข้อมูลจริงได้ |

- สีใช้ semantic token เท่านั้น สีสถานะห้อง (กำหนดไว้ที่ `ROOM_STATUS_STYLE` ใน `components/dorm/room-grid.tsx` เพื่อให้ Live Room Map จริงใช้ชุดเดียวกัน) ใช้คู่ status token ที่มีทั้งพื้นและตัวอักษร และสลับเองใน dark mode: ว่าง = `status-lime`, ติดจอง = `status-yellow`, มีผู้เช่า = `background-tertiary-default` + `text-tertiary`, ปิดปรับปรุง = `status-rose` ต้องมีเลขห้องและ legend กำกับเสมอ ไม่สื่อด้วยสีอย่างเดียว
- Typography: H1 `text-title-1-medium`, H2 `text-title-2-medium`, หัวการ์ด `text-headline-semibold`, เนื้อหา `text-body-regular`
- การ์ด `rounded-3xl border-border-button-default`, pill `rounded-full`
- ความกว้างเนื้อหา `max-w-6xl`, ระยะระหว่าง section `py-16` (มือถือ `py-12`)
- ใช้ logical properties (`ms/me`, `text-start`) เพื่อรองรับ RTL ในอนาคต

### Rendering (Next.js 16, `cacheComponents: true`)

- หน้า `/` เป็น static shell ทั้งหมด ยกเว้น
  - ปุ่ม CTA เจ้าของหอที่เปลี่ยนตามสถานะล็อกอิน → แยกเป็น async component ใน `<Suspense>` (fallback = ปุ่ม "ลงประกาศหอพักฟรี")
  - `live-stats.tsx` ใช้ `"use cache"` ไม่ต้องอยู่ใน request time
  - แท็บ `?for=owner`: page ส่ง `searchParams` (Promise) ให้ client component ที่ `use()` ภายใน `<Suspense>` (fallback = แท็บผู้เช่า) เฉพาะบล็อกนี้ที่ stream ส่วนอื่นยัง static (`useSearchParams` อ่านค่าไม่ได้หลัง hydrate ในโหมด partial prefetching จึงไม่ใช้)
- Client component เฉพาะส่วนที่ต้องโต้ตอบ (calculator, segmented control, accordion)
- ไม่มีรูปภาพหนัก ภาพประกอบเป็น HTML/CSS → LCP คือ H1

### SEO

- `metadata` ของ `/`: ใช้ title/description เดิมใน `app/layout.tsx` + `openGraph` (ชื่อ, คำอธิบาย, `locale: "th_TH"`, รูป OG)
- รูป OG: `app/opengraph-image.tsx` (ImageResponse) ข้อความ "DormDee – หาหอพัก ห้องว่างจริง จองผ่านแชท"
- JSON-LD: `Organization` + `WebSite` (มี `SearchAction` ชี้ `/search?q={search_term_string}`) + `FAQPage`
- Heading ลำดับถูกต้อง: H1 เดียว, ทุก section มี H2

### Accessibility

- ทุก section เป็น `<section aria-labelledby>` ชี้ไปที่ H2
- ผังห้องตัวอย่าง: `role="img"` + `aria-label` สรุป เช่น "ตัวอย่างผังห้อง: ว่าง 5 ห้อง ติดจอง 2 ห้อง มีผู้เช่า 5 ห้อง"
- Focus ring `focus-visible:ring-2 focus-visible:ring-border-focus-ring` ทุก element ที่โต้ตอบได้
- คอนทราสต์ข้อความ ≥ 4.5:1 ทั้ง light และ dark
- เคารพ `prefers-reduced-motion` (ไม่มี animation ตอนเลื่อนถ้าผู้ใช้ปิด)

### Analytics events (เตรียมชื่อไว้ ยังไม่ต้องต่อเครื่องมือ)

`landing_search_submit`, `landing_area_click`, `landing_owner_cta_click`, `landing_how_it_works_tab`, `landing_cost_demo_change`, `landing_faq_open`
